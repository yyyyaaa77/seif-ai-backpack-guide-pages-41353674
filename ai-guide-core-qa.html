00 / 结论速览

先理解任务，再决定问什么和推荐什么

AI 导购的核心不是把用户变成参数专家，而是把用户描述的生活问题转成可确认、可筛选、可解释的决策条件。

问题一句话回答关键保障
如何形成核心诉求从场景、任务、人群、约束与优先项重建真实问题。先确认主场景，再形成可验证条件。
如何转成结构化属性模型抽取字段，受控词表归一化，规则层区分硬条件与软偏好。商品参数只来自真实知识库。
如何多轮澄清在 1–3 轮内只问最能改变候选集的问题。一次一问、可跳过、条件不丢失。
如何控制幻觉生成前限制、生成后校验、异常降级和人工兜底。事实错误与高风险越界零容忍。
01 / 核心诉求

如何把模糊需求转化为核心诉求

核心诉求不是更长的关键词列表，而是一句能指导取舍的需求判断。它说明谁使用、在什么场景完成什么任务、必须满足什么限制，以及条件冲突时优先保留什么。

01

区分字面词与真实意图

“轻一点”可能指自重低、肩带减负、容量适中或视觉轻盈，不能直接等同于重量数字。

02

锁定主场景

先判断通勤、校园、带娃、穿搭或户外，这会决定容量、背负、风格与功能优先级。

03

识别关键载荷

确认是否装电脑、课本、母婴用品、水杯或户外装备，将生活需求转成结构和容量条件。

04

确认硬约束

预算、颜色禁忌、尺寸、年级或年龄、库存必须明确，并进入不可绕过的过滤条件。

05

确认优先级

在轻量、容量、风格和价格之间做取舍，形成排序权重与可接受的商品风险。

示例：想要适合夏天、轻一点的双肩包

用户原话

“想要适合夏天、
轻一点的双肩包。”

初步理解

可能重视透气、轻装和肩部减负；但还不知道谁使用、主要场景、预算、需要装什么。系统应先问场景，而不是直接抛商品。

原始表达夏天、轻一点
拆解信号透气 / 轻量 / 场景未知
关键追问谁用、主要在哪用
补充条件14英寸电脑、300元内
核心诉求轻量通勤、非黑、可装电脑
最终需求用户需要一款适合夏季轻装通勤、能放下14英寸电脑和水杯、优先轻量和透气、预算不超过300元且不使用黑色的通勤双肩包。
原始表达可提取信号不能直接假设优先追问
适合夏天可能重视透气、轻装和防泼水一定是户外包主要通勤、上学还是出游
轻一点可能指自重、背负或容量适中重量必须低于某个固定值主要装什么、会背多久
双肩包确认品类边界已经知道尺寸、容量和风格是否带电脑、书本或母婴用品
02 / 结构化与澄清

AI 如何形成可筛选条件，并通过多轮对话澄清歧义

大模型负责语义理解和表达，规则层负责执行硬条件，商品知识库负责提供真实规格、价格和库存。任何推断都不能覆盖用户已确认的禁忌。

2.1 从口语到结构化属性

语义抽取场景 / 人群 / 用途 / 预算 / 禁忌
词表归一妈咪包、妈妈包 → 妈咪包
状态标记明确 / 推断 / 冲突 / 未提及
条件分流硬条件 / 软偏好 / 缺失字段
候选排序规则门控 + 多目标评分
字段状态示例是否参与筛选处理方式
明确预算300元、不要黑色可以作为硬条件直接过滤，不允许模型覆盖
推断夏天 → 透气更好仅作为软排序解释时标注为偏好推断
冲突轻便且装很多书不能直接筛选追问重量与容量优先级
未提及未说明电脑尺寸先不做硬限制根据场景决定是否追问
关键原则明确条件进入硬过滤，推断只进入排序，未知条件不补全。结构化结果必须保留来源、状态和必要证据。

2.2 多轮追问与歧义澄清

系统支持多轮对话，但主动追问通常控制在 1–3 轮，每轮只问一个最可能改变候选集的问题，并提供可直接选择的答案。

自由表达口语、语音、快捷标签
首轮解析展示已理解条件
置信度判断足够推荐、不足追问、冲突确认
筛选与排序硬条件先行，再排偏好
解释与跟进主推荐 + 差异候选 + 取舍

追问规则

  • 一次只问一个问题。
  • 给出 3–4 个生活化选项。
  • 最多主动追问 3 轮。
  • 用户拒绝回答时使用低风险默认值。
  • 默认假设必须显式展示。

结果后的继续追问

  • “更便宜”：保留其他条件，只调预算权重。
  • “轻一点”：提高重量与背负优先级。
  • “换韩系”：只调风格，不丢电脑尺寸。
  • “不喜欢这款”：记录原因并重排。
歧义类型示例推荐澄清方式
词义歧义“轻一点”是自重、背负还是轻装给出重量轻、不压肩、容量不必大三个选项
场景缺失“夏天用”可能是通勤、旅行或带娃先确认主要使用场景
条件冲突很轻、大容量、低价同时出现请用户选择必须保留的一个条件
主观偏好“好看”“高级感”没有统一标准转为颜色、轮廓、材质与风格候选
指代不明“这个太商务”“刚才那款”结合上轮商品或让用户点选
想要适合夏天、轻一点的双肩包。
你主要用它做什么？上班通勤、学生上课、带娃出门，还是周末轻户外？
上班通勤，装14英寸电脑和水杯，预算300元，不要黑色。
明白。我会优先看轻量、透气和肩带舒适，过滤掉超预算、无电脑仓、黑色和缺货商品。
03 / 风险治理

哪些情况会导致答错、幻觉或推荐不准

错误通常来自四类根因：用户信息不完整、语言存在歧义、商品事实不可靠、排序目标发生偏移。治理需要覆盖生成前、生成后和异常降级三个环节。

风险类型典型错误根因处理方式
需求误读把“轻”全部理解为重量低口语词存在多重含义保留证据并追问；推断只参与排序
场景混淆“带娃”被推荐儿童书包人群和用途未区分先确认宝宝年龄、时长和装载物
禁忌遗漏用户不要黑色仍推荐黑色生成层越过硬条件禁忌在模型前由规则强制过滤
条件冲突轻便、大容量、低价同时满足需求本身不可兼得请用户确认优先级，不虚构商品
规格幻觉商品页无重量却生成0.6kg模型用品类常识补全字段为空即回答“未提供”
价格库存幻觉承诺有货、明天送达缓存过期或模型记忆以实时接口或带时间戳快照为准
认证幻觉将母婴风格写成安全认证营销语义被强化只引用官方认证原文，无证据不扩展
排序偏差佣金或库存压力抬高商品商业目标压过相关性商业权重设上限，硬条件先行
上下文漂移“更便宜”后丢掉电脑尺寸对话状态未继承只更新新条件，保留已确认字段
Prompt 注入用户要求忽略规则或编造库存系统指令和用户文本未隔离敏感请求拒答，事实不采用伪造数据
事实错误必须阻断价格、库存、型号、认证和链接错误进入阻断级告警，不继续生成主推荐。
理解错误回到澄清不争辩，先复述新条件，再判断旧候选，必要时让用户确认优先级。
主观偏好保留选择权风格没有客观唯一解，应展示候选差异和取舍，不输出“绝对最适合”。
无证据不做强承诺母婴、儿童和户外安全信息没有官方依据时，采用保守话术或转人工。

三层控制与降级顺序

生成前

结构化字段、受控词表、硬条件预过滤，商品事实只从知识库输入。

生成后

事实校验、禁忌复查、链接图片巡检与风险措辞检查。

监控层

用户纠错、点击失败、负反馈、人工抽检和固定评测集回归。

异常降级顺序：追问关键问题 → 显示默认假设 → 明确无法确认 → 给出受控放宽选项 → 转人工或官方渠道。

04 / 落地检查

上线前必须通过的检查项

这套方案的目标不是让 AI 说得更确定，而是让不确定的信息被正确处理。

用户只说一句模糊需求时，系统先确认场景和用途，不直接抛商品。
每条推荐都有真实商品链接、图片、型号、价格与库存状态。
硬条件和禁忌在模型生成前执行，模型不能覆盖。
每条推荐理由都能映射到商品事实或有来源的评论洞察。
对话最多主动追问 3 轮，超过后使用默认假设并明确展示。
用户否定某款商品后，其他已确认条件不被重置。
无完全匹配时说明原因，并提供可操作的放宽路径。
母婴、儿童和户外安全等高风险问题没有无证据的绝对承诺。
价格、库存和链接具有同步时间、巡检和人工抽检机制。
商品事实错误率、禁忌违反率和可追溯解释覆盖率进入日常监控。
最终判断标准用户能看懂推荐依据，能修改系统理解，能知道哪些条件没有被满足，并最终买到符合真实场景的商品。
